## 🧭 About

I'm **Radhakishan Jangid**, a Senior Software Engineer with **7+ years** building production web and mobile products end to end — from the React UI down to the Node.js / PHP APIs and the deployment that ships them. I currently work with US-based product and engineering teams at **Cachetech Advisor Solutions**, building scalable fintech systems: workflow management, multi-tenancy architecture, and React Native mobile delivery.

I care about systems that stay maintainable as they grow — feature-modular React, clean REST boundaries, and CI/CD that removes humans from the deploy path. Lately I'm **building in public** with native macOS tools and open-source developer utilities.

## 🚀 Featured Projects

<details>
<summary><b>🔷 MacEdits</b> — local-first macOS reel editor for creators</summary>
<br/>

**Architecture:** A backend-free SwiftUI desktop app where recording, timeline editing, and export run entirely on-device via AVFoundation and ScreenCaptureKit — no cloud dependency in the creator workflow.

| Dimension | Detail |
|-----------|--------|
| Stack | Swift, SwiftUI, AVFoundation, ScreenCaptureKit, macOS |
| Scope | Recording studio (camera / screen / both), timeline trim·split·reorder·ripple, captions & export |
| Model | Local-first — all media processing on-device |
| Status | Open Source · Build in Public (2026) |

**What I Learned:** Driving real-time media pipelines through AVFoundation forces you to think in time samples and buffer lifecycles rather than request/response — a very different mental model from web engineering.

[![Repo](https://img.shields.io/badge/GitHub-111827?style=flat-square&logo=github&logoColor=white)](https://github.com/radhakishan404/MacEdits)

</details>

<details>
<summary><b>🔷 SSHipIt</b> — continuous deployment over SSH for Node / Next.js / React</summary>
<br/>

**Architecture:** A self-hosted CD utility that runs reliable deployment pipelines over plain SSH, giving small teams a CI/CD pattern without locking into a managed platform.

| Dimension | Detail |
|-----------|--------|
| Stack | Node.js, Express, SSH, WebSocket, CI/CD |
| Targets | Node.js, Next.js, React applications |
| Value | Simple, self-hosted deploys — no platform lock-in |
| Status | Open Source · Live (2026) |

**What I Learned:** Designing for other developers' machines means defensive defaults and clear failure output matter more than feature count — the tool has to fail loudly and recover predictably.

[![Site](https://img.shields.io/badge/Live-10B981?style=flat-square&logo=vercel&logoColor=white)](https://sshipit.vercel.app/) [![Repo](https://img.shields.io/badge/GitHub-111827?style=flat-square&logo=github&logoColor=white)](https://github.com/radhakishan404/sshipit)

<summary><b>🔷 Nirula's — Online Ordering + POS</b> — high-traffic React/Node food delivery platform</summary>
<br/>

**Architecture:** Migrated a legacy AngularJS storefront to a feature-modular React + Redux frontend backed by Node.js/Express APIs, with lazy-loaded modules and a dedicated customization/pricing service for menu items.

| Dimension | Detail |
|-----------|--------|
| Stack | React, Redux, Node.js, Express, AWS, Google Analytics |
| Scope | Storefront + branch POS: cart, coupons, OTP, live location, branch dashboards |
| Engineering | Per-feature module split, lazy loading, server-side pricing/customization |
| Status | Live |

**What I Learned:** The hardest part wasn't the UI — it was modeling product customization and pricing so the same rules held across storefront and POS. Pushing that logic into a single Node API kept both clients consistent.
